# 赛题四全文索引优化

基于 `e6efc0de33cd18a13b24ea183a7b6660bffbfc53`，分支 `perf/task4-fulltext`。

## 瓶颈与修改

源码热路径分析显示以下重复工作。本次没有使用数据库 profiler，以下是代码路径依据，并非完整实例的热点采样结论。

1. `ObFTCharUtil::do_classify` 原来在字母、数字、中文和其他 CJK 判断中重复解码相同字符。中文字符通常解码三次，标点通常解码四次。现在一次解码后复用 Unicode 值，保留原判断顺序、字符集分派和失败返回值。全角字母、数字仍优先于 OTHER_CJK 分类。
2. IK 外层已读取字符地址、长度和类型，四个处理器通过 `process()` 又各读取一次。现在直接调用已有的虚函数 `do_process()`，保留处理器顺序及全部处理；游标仍由原外层 `step_next()` 推进。已检查四个处理器均不推进游标。
3. `filter_special_marks` 原来扫描全部字节并计数。现在一旦发现非标点且非控制的字节就返回有效判断。保留原字符表谓词、逐字节语义和空词元行为。

没有修改词典、分词规则、词频、倒排数据格式、查询逻辑、官方基准、计时逻辑或评分规则。没有新增跨请求共享缓存。

组件中位耗时下降约 38.5%。这是隔离分类函数的微基准，不能换算为全文索引构建、TOKENIZE、MATCH 或官方综合得分。完整数据库中的收益取决于分类所占比例、其他开销及机器负载。
